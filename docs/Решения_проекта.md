# Решения проекта

Решения, которые меняют договорённости между частями системы — чтобы каждый
участник узнавал о них отсюда, а не из упавшей сборки. Новые записи сверху.
Точные контракты — в [`api.md`](api.md), детали MAX — в [`max-notes.md`](max-notes.md).

## 24.09.2026 — Модель заявки мини-аппа приведена к модели api

**Касается:** Михаил (`miniapp/`). На синк 24.09, 21:00.

**Почему.** Аудит 23.09, пункт В8: мини-апп и api описывали заявку по-разному —
разные статусы, номер договора вместо жителя, описание, которому негде храниться.
При подключении мини-аппа к api одна модель должна стать главной. Главная — модель api.

**Что меняется для мини-аппа:**

| Было в `miniapp/` | Стало |
|---|---|
| Житель вводит номер договора | Поля нет. Жителя определяет api по `initData` MAX (подпись проверяется на сервере); с клиента id жителя не передаётся |
| Адрес — из договора | Адрес — из дома жителя (`houses`) |
| Статусы `review` / `work` / `done` | Статусы api: `new` / `in_progress` / `resolved`. Русские подписи остаются на стороне мини-аппа: «В рассмотрении» / «В работе» / «Решено» |
| Описание проблемы негде хранить | Новое поле заявки `description` |
| Список заявок — моки | Новый эндпоинт «мои заявки»; api определяет жителя по `initData` |
| Тип проблемы `pipe`, `electricity`… | Передаётся в `problem_type`. Перечень кодов согласовать с Павлом — по нему будет работать маршрутизация (`rules.yaml`) |

**Кто делает.** Правки в `miniapp/` вносятся в рамках текущей задачи (шаг «мини-апп»).
Михаилу — учесть новую модель в дальнейшей работе над экранами и **не менять
`miniapp/src/types/domain.ts` параллельно**, чтобы не получить конфликт. Точный контракт
появится в `api.md` вместе с кодом.

## 24.09.2026 — Вход жителя и чат дома

- **Вход — кнопкой MAX «Поделиться контактом»** (`request_contact`), а не вводом номера.
  MAX подписывает контакт токеном бота, подделать чужой номер нельзя. Номер ищется
  среди жителей, заранее заведённых УК. SMS/звонков нет. Работает ли кнопка в
  веб-клиенте MAX — проверяется 24.09; если нет, для веба запасной путь — ввод номера
  текстом после «+7».
- **Одна квартира на номер телефона** — осознанное ограничение MVP.
- **Проверка подписи `initData` мини-аппа делается сейчас**, а не отдельной задачей:
  без неё «вход через MAX» — фикция, а закрытие api (аудит, Б1) без неё парализует
  мини-апп.
- **Чат — на дом, не на подъезд.** Ссылку на чат хранит дом (`houses.chat_link`),
  её заполняет УК.
- **Дом жителя** определяется по данным УК; если их нет — по QR-коду (в нём случайный
  `invite_code` дома, а не номер, чтобы нельзя было перебрать чужие дома) или по
  адресу, введённому вручную (улица + дом). При расхождении QR и данных УК верим УК.
