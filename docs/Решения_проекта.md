# Решения проекта

Решения, которые меняют договорённости между частями системы — чтобы каждый
участник узнавал о них отсюда, а не из упавшей сборки. Новые записи сверху.
Точные контракты — в [`api.md`](api.md), детали MAX — в [`max-notes.md`](max-notes.md).

## 24.09.2026 — Заявка в диалоге бота; сначала — опасность (КТ-2)

Согласовано 24.09.2026 — автомат диалога, по CLAUDE.md только по согласованию.
Делается шагами: **A** — опасность (сделан), **B** — обычная заявка и зона
собственника, **C** — «Мои заявки» и «статус N».

- **Заявку житель подаёт в диалоге с ботом.** Работает без одобрения мини-аппа и
  при белых списках (всё идёт через MAX). Мини-апп потом станет второй формой на
  тех же маршрутах api; кнопка «Отправить заявку ЖКХ» остаётся в меню.
- **Опасность — до обычной заявки.** «Сообщить о проблеме» первым вопросом
  спрашивает: газ / искрит проводка / заливает / обычная проблема.
- **Опасность по кнопке:** сразу инструкция «что делать прямо сейчас» + телефон
  аварийной службы УК (`EMERGENCY_PHONE`), затем аварийная заявка с номером
  (`problem_type`: `gas_smell`, `sparking`, `flooding`). Инструкция уходит первой
  и не зависит от api: заявка может не создаться, а что делать при газе, человек
  должен узнать в любом случае.
- **Страховка по словам:** «пахнет газом», «искрит», «затопило» и т. п. в любом
  тексте, на любом шаге и даже без входа → инструкция сразу. Заявка — только по
  кнопке «Да, это авария»: «газ отключили» тоже совпадёт, ложная аварийная
  заявка диспетчеру не нужна. Текст жителя уходит в описание заявки.
- **Повторы:** аварийная заявка того же типа от того же жителя в течение 30 минут
  не дублируется — бот напоминает номер первой.
- **Зона собственника** (шаг B): «где?» → «в квартире» → уточнение границы
  (вода — до/после первого крана от стояка, электричество — до/после квартирного
  счётчика). За границей — объяснение, заявка в УК не создаётся.
- **Павел:** проверить тексты экстренных инструкций до демо (безопасность людей);
  перечень опасных типов и границы зоны собственника перенести в
  `config/rules.yaml`, когда он появится. Сейчас — в коде с пометкой TODO.

## 24.09.2026 — Жильцов и дома ведёт УК

Согласовано 24.09.2026 — это схема БД, по CLAUDE.md только по согласованию.
Миграция `0003`, контракт — [`api.md`](api.md), «Дома и жители — для УК»,
команды — [`RUN.md`](RUN.md), «Дома и жители».

- **Инструмент УК — закрытые маршруты api `/admin/*` + команда на сервере**
  (`docker compose exec api node dist/cli.js`), включая импорт списка из CSV
  (выгрузка из Excel). Веб-панели УК пока нет: для неё нужен вход сотрудников,
  это отдельная задача. Панель потом ляжет на те же маршруты.
- **У жителя:** дом, подъезд, этаж, квартира, номер договора — все необязательные.
- **Номер договора — справочное поле УК.** У жителя его не спрашиваем; вход
  по-прежнему по контакту MAX (решение о мини-аппе ниже не меняется).
- **Удаление — архив.** Войти нельзя, заявки и история остаются. Номер ушедшего
  жильца можно завести заново — новой записью.
- **Смена телефона УК снимает привязку к MAX:** житель входит заново.
- **Дома УК заводит тем же инструментом**: адрес, ссылка на чат. Удаления домов нет.

## 24.09.2026 — Меню бота и «Чат дома» (шаг 3)

Согласовано 24.09.2026 — это автомат диалога, по CLAUDE.md только по согласованию.

- **Меню** — после входа, на `/start` и на любой непонятный текст: «Чат дома»,
  «Отправить заявку ЖКХ» (кнопка `open_app`, username бота берётся из `GET /me`).
  Эхо убрано.
- **«Чат дома»:** дом известен — адрес и кнопка-ссылка на чат (или «чат ещё не
  создан — обратитесь в УК»); неизвестен — бот просит адрес.
- **Ожидание адреса** — в памяти бота. Выход: найденный дом, `/start`, кнопка меню,
  «Отмена», **15 минут без действий**. Неверный адрес — подсказка, ожидание
  продолжается.
- **Нормализация адреса — в api**: нижний регистр, без типов улиц и «д./дом»,
  номер — последнее слово с цифрой. Известный риск: улицы с цифрой в названии —
  на реальных домах проверить.
- **QR до входа:** код дома держится в памяти до входа (час), потом применяется.
- **Новые маршруты api — под `/residents/…`**, чтобы их закрывала уже стоящая
  защита от внешних запросов.

## 24.09.2026 — Модель заявки мини-аппа приведена к модели api

**Касается:** Михаил (`miniapp/`). На синк 24.09, 21:00.

**Почему.** Аудит 23.09, пункт В8: мини-апп и api описывали заявку по-разному —
разные статусы, номер договора вместо жителя, описание, которому негде храниться.
При подключении мини-аппа к api одна модель должна стать главной. Главная — модель api.

**Что меняется для мини-аппа:**

| Было в `miniapp/` | Стало |
|---|---|
| Житель вводит номер договора | Поля нет. Жителя определяет api по `initData` MAX (подпись проверяется на сервере); с клиента id жителя не передаётся |
| Адрес — из договора | Адрес — из дома жителя (`houses`) |
| Статусы `review` / `work` / `done` | Статусы api: `new` / `in_progress` / `resolved`. Русские подписи остаются на стороне мини-аппа: «В рассмотрении» / «В работе» / «Решено» |
| Описание проблемы негде хранить | Новое поле заявки `description` |
| Список заявок — моки | Новый эндпоинт «мои заявки»; api определяет жителя по `initData` |
| Тип проблемы `pipe`, `electricity`… | Передаётся в `problem_type`. Перечень кодов согласовать с Павлом — по нему будет работать маршрутизация (`rules.yaml`) |

**Кто делает.** Правки в `miniapp/` вносятся в рамках текущей задачи (шаг «мини-апп»).
Михаилу — учесть новую модель в дальнейшей работе над экранами и **не менять
`miniapp/src/types/domain.ts` параллельно**, чтобы не получить конфликт. Точный контракт
появится в `api.md` вместе с кодом.

## 24.09.2026 — Вход жителя и чат дома

- **Вход — кнопкой MAX «Поделиться контактом»** (`request_contact`), а не вводом номера.
  MAX подписывает контакт токеном бота, подделать чужой номер нельзя. Номер ищется
  среди жителей, заранее заведённых УК. SMS/звонков нет. Работает ли кнопка в
  веб-клиенте MAX — проверяется 24.09; если нет, для веба запасной путь — ввод номера
  текстом после «+7».
- **Одна квартира на номер телефона** — осознанное ограничение MVP.
- **Проверка подписи `initData` мини-аппа делается сейчас**, а не отдельной задачей:
  без неё «вход через MAX» — фикция, а закрытие api (аудит, Б1) без неё парализует
  мини-апп.
- **Чат — на дом, не на подъезд.** Ссылку на чат хранит дом (`houses.chat_link`),
  её заполняет УК.
- **Дом жителя** определяется по данным УК; если их нет — по QR-коду (в нём случайный
  `invite_code` дома, а не номер, чтобы нельзя было перебрать чужие дома) или по
  адресу, введённому вручную (улица + дом). При расхождении QR и данных УК верим УК.
