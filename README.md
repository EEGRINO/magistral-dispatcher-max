# Диспетчер обращений по авариям и заявкам

Чат-бот для мессенджера MAX: житель описывает проблему в чате, бот
превращает это в заявку и доводит до исполнителя. Трек «Умный город».

Статус: Д-10, каркас + рабочее эхо. Сценарий жителя ещё не реализован.

## Запуск

```bash
cp .env.example .env              # подставить MAX_BOT_TOKEN из @MasterBot
git config core.hooksPath .githooks   # включить проверку секретов перед коммитом
docker compose up --build
```

Поднимется три сервиса: `bot`, `api`, `db`.

Проверка:

- `curl http://localhost:3000/health` → `{"status":"ok",...}`
- написать боту в MAX `/start` → «Бот на связи. Напиши что-нибудь — я повторю.»
- написать боту любой текст → он вернёт тот же текст

Логи: `docker compose logs -f bot`

## Структура

| Каталог | Что внутри |
|---|---|
| `bot/` | диалог с жителем через MAX Bot API (long polling) |
| `api/` | Fastify, бизнес-логика — пока только `/health` |
| `db/` | миграции PostgreSQL — каркас |
| `config/` | `houses.json`, `rules.yaml`, `norms.yaml` — справочники |
| `docs/` | [`max-notes.md`](docs/max-notes.md) — источник правды по MAX Bot API |

## Для разработчиков

обращение с секретами, что нельзя генерировать без согласования.
