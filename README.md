# Диспетчер обращений по авариям и заявкам

Чат-бот для мессенджера MAX: житель описывает проблему в чате, бот
превращает это в заявку и доводит до исполнителя. Трек «Умный город».

Статус: Д-9, КТ-1 — сквозной провод MAX → бот → api → БД работает.
Сценарий диалога с жителем и маршрутизация ещё не реализованы.

## Запуск

```bash
cp .env.example .env              # подставить MAX_BOT_TOKEN из @MasterBot
git config core.hooksPath .githooks   # включить проверку секретов перед коммитом
docker compose up --build
```

Поднимется три сервиса — `bot`, `api`, `db` — плюс одноразовый `migrate`,
который применит миграции до старта `api`.

Проверка:

- `curl http://localhost:3000/health` → `{"status":"ok","db":"ok",...}`
- написать боту в MAX `/start` → «Бот на связи. **Ваш ID: N**. …»
  (наличие ID означает, что запись дошла до БД через api)
- написать боту любой текст → он вернёт тот же текст

Логи: `docker compose logs -f bot`

Подробная инструкция и разбор типичных проблем первого запуска —
[`docs/RUN.md`](docs/RUN.md). Описание проблемы, решения и статуса проекта
для защиты — [`docs/EXPLANATORY-NOTE.md`](docs/EXPLANATORY-NOTE.md).

## Структура

| Каталог | Что внутри |
|---|---|
| `bot/` | диалог с жителем через MAX Bot API (long polling) |
| `api/` | Fastify: жители, заявки, `/health` |
| `db/` | миграции PostgreSQL + seed тестовых данных |
| `config/` | `houses.json`, `rules.yaml`, `norms.yaml` — справочники |
| `docs/` | [`api.md`](docs/api.md) — контракт api; [`max-notes.md`](docs/max-notes.md) — источник правды по MAX Bot API |
