# CLAUDE.md

Чат-бот «Диспетчер обращений по авариям и заявкам» для мессенджера MAX.
Трек «Умный город». Хакатон MAX, демо — 30.09.2026.

## Стек

- Node.js 22 + TypeScript (ESM, `"type": "module"`)
- MAX Bot API — **long polling**, свой тонкий клиент на `fetch`, без сторонних SDK
- Fastify — HTTP API
- PostgreSQL 16
- docker-compose — единственный поддерживаемый способ запуска

## Структура монорепо

```
bot/      диалог с жителем через MAX Bot API (long polling)
api/      бизнес-логика, Fastify
db/       миграции Postgres
config/   houses.json, rules.yaml, norms.yaml — справочники, редактируются без пересборки
docs/     max-notes.md — источник правды по MAX Bot API
```

Каждый сервис — самостоятельный npm-пакет со своим `package.json`, `tsconfig.json` и
`Dockerfile`. Общего корневого `package.json` и workspaces нет: для MVP это лишняя связность,
а образы собираются независимо.

## 🔒 Секреты — жёсткое правило

- Секреты живут **только** в `.env`. `.env` в `.gitignore` и никогда не коммитится.
- В коде секретов нет — ни как дефолтное значение, ни как фолбэк, ни в комментарии,
  ни в тесте, ни в примере в документации.
- Читать только через `process.env.*`. Конструкция вида
  `process.env.MAX_BOT_TOKEN ?? 'f9LHod...'` — запрещена.
- `.env.example` содержит **только плейсхолдеры**. Он коммитится, поэтому настоящее
  значение в нём — это утечка.
- Секреты не попадают в логи. Логировать можно факт наличия токена и его длину, не сам токен.
- Проверка автоматическая: `.githooks/pre-commit` → `scripts/check-secrets.sh`.
  Включается один раз: `git config core.hooksPath .githooks`.
- Хук ловит только новые утечки в staged-файлах. Полный аудит **истории** git — отдельная
  задача на Д-3.

## Источник правды по MAX Bot API

[`docs/max-notes.md`](docs/max-notes.md) — единственный авторитетный источник по
MAX Bot API, Bridge и UI в этом проекте.

**Не доверять** сторонним примерам, статьям, ответам на форумах и npm-SDK: в июле 2026
MAX сменил базовый домен на `platform-api2.max.ru` и запретил передачу токена
query-параметром. Подавляющее большинство материалов в интернете описывает мёртвый API
и вернёт 401.

Не доверять и памяти модели — она застала старый API.

Если реальное поведение API разошлось с `docs/max-notes.md` — правим `docs/max-notes.md`
тем же коммитом и указываем дату проверки. Файл, который врёт, хуже отсутствующего.

## Правило согласования: FSM и схема БД

**Не генерировать самостоятельно, без явного согласования с разработчиком:**

- логику конечного автомата диалога с жителем (состояния, переходы, условия выхода,
  обработку отмены и таймаутов);
- схему БД — таблицы, поля, связи, индексы, миграции.

Это ядро продукта и предмет оценки жюри. Здесь нужен осознанный дизайн, а не правдоподобная
заготовка: неудачная схема на Д-10 стоит переписывания всего на Д-3.

Порядок работы: предложить варианты и trade-off'ы текстом → дождаться решения → реализовать.
Код пишем после согласования, не до.

## Запуск

```bash
cp .env.example .env        # подставить настоящий MAX_BOT_TOKEN
git config core.hooksPath .githooks
docker compose up --build
```

Проверка живости: `curl http://localhost:3000/health`, и `/start` боту в MAX.

Бот на long polling исходящими соединениями — порт наружу не слушает,
публичный HTTPS-домен и туннель не нужны.
